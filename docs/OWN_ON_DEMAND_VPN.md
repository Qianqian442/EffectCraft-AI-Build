# EffectCraft 自有按需 VPN 实施方案

状态：实现设计已入库；尚未接入 APK，不能视为已可连接的 VPN。

## 目标与边界

- 主 APK 内置 Android `VpnService` 客户端；不是要求用户安装第三方 VPN。
- 管理版手机作为 EffectCraft 自有出口网关。主 APK 通过现有加密 P2P 网络与管理版建立隧道；直连不可达时才尝试现有 P2P 中继。
- VPN 只服务 EffectCraft 账号 API，不接管手机上其他应用的流量。
- 注册/登录按钮触发一次连接；HTTP 请求成功、失败、超时或取消后都关闭隧道。
- 管理版发出封号/解禁事件后，用户端由系统推送唤醒，再短暂连接 VPN 拉取正式状态；收到并保存后立即关闭。
- 封号期间只使用本地截止时间倒计时，不周期性调用 Worker。到期本地可恢复界面，但服务端仍是最终权限来源。
- Cloudflare Worker 继续只处理账号 API，不充当 VPN 网关。

## 为什么让管理版手机作为出口

仓库已有主 APK 和管理版 APK 的 libp2p/Noise 加密节点。相比直接依赖不受信任的开放代理，管理版手机作为可信出口更符合“自己做”的目标，也不需要先租购 VPS。

管理版手机必须保持联网并运行管理版服务。它需要能够访问 Cloudflare Worker；若管理版手机本身也无法到达 Worker，VPN 客户端不能凭空创造外网出口。公网 P2P 中继只负责帮助两端建立加密传输，不等于它本身提供互联网出口。

## 数据路径

```text
EffectCraft 注册/登录或单次状态拉取
  -> Android VpnService（只路由 EffectCraft 的目标账号流量）
  -> 本地 TUN / userspace tunnel
  -> libp2p 加密数据流（Noise 身份认证）
  -> 管理版手机出口网关
  -> 原样转发 TLS 字节流
  -> https://<configured-worker>.workers.dev
  -> 响应沿同一加密通道返回
```

TLS 必须端到端保留：管理版只转发 TCP 字节，不解密、不改写账号 HTTPS 内容。网关默认只允许配置好的 Cloudflare Worker 主机名和 443 端口，拒绝任意目标地址，避免把管理版手机变成开放代理。

## Android 客户端要求

1. 声明 `VpnService`，使用 `VpnService.prepare()` 请求系统授权；拒绝授权时停止本次受保护操作，不能伪装成 VPN 已连通。
2. `Builder.addAllowedApplication("com.artcraft.effectcraft")` 限定仅主 APK 流量进入隧道；不影响 QQ、微信、浏览器和其他手机应用。
3. 只添加 Worker 目标地址所需路由，不默认接管 `0.0.0.0/0` 全设备流量。
4. 隧道底层 P2P socket 必须调用 `VpnService.protect()` 或绑定到底层网络，防止自己的隧道连接再次进入 TUN 造成循环。
5. 连接状态机：`IDLE -> AUTHORIZING -> CONNECTING -> ACTIVE -> STOPPING -> IDLE`。每次操作带唯一 task ID；并发请求复用同一活动隧道，引用计数归零时关闭。
6. 所有退出路径（成功、HTTP 错误、网络错误、超时、取消、服务撤销、应用退出）都在 `finally`/服务清理路径关闭 TUN、P2P 子流和前台通知。
7. 建立失败时不锁死本地编辑器；账号受保护操作显示明确失败原因并允许重试。

## 管理版网关要求

- 新增独立的 VPN TCP 转发协议流，不复用账号 RPC 的 JSON 请求/响应协议。
- 每条流必须由已认证的 libp2p peer 身份建立，并限制并发数、目标主机、目标端口、空闲超时、单流缓冲区和总带宽。
- 只转发 `workers.dev` 配置的 Worker HTTPS 流量；保留 TLS 字节透传。
- 用户端只允许连接管理员可信身份；不能因“能连上任意 P2P 节点”就视为管理员。
- 管理版退出、撤销信任、网络切换或管理员节点不可达时，客户端必须结束 VPN，不应把流量静默发给未知代理。

## 封号/解禁事件与额度控制

- 管理版封号/解禁操作由 Worker 写入唯一事件 ID、状态、服务端截止时间，并触发一次系统推送。
- 推送只包含随机事件 ID 和最少唤醒信息，不把账号令牌、封号原因或敏感资料放进推送负载。
- 主 APK 收到推送后只拉取一次正式状态；按事件 ID 去重；成功存档后关闭 VPN。
- 需为 OPPO Push、Huawei Push Kit、FCM 建立可配置适配层。厂商 App ID/Key、FCM 服务帐号等凭据必须通过各厂商控制台和安全配置提供；仓库不得提交密钥。
- 如果厂商推送不可用、系统强制停止应用或设备离线，不能承诺即时通知；应用下次启动/恢复时补查一次最新状态。
- 不用固定间隔轮询，不在每个代理/中继候选上请求 Worker `/health`。节点探测只做传输层可达性检查。
- 注册、登录、封号读取、解禁读取各自只发起必需的业务 API 请求；本地倒计时不访问 Worker。

## 实施顺序（禁止跳步发版）

1. 完成并单测 P2P 双向 TCP 流、管理员身份校验、Worker 主机名白名单、TLS 透传和 socket protect。
2. 加入 Android VpnService、权限申请、TUN 路由和服务启停状态机。
3. 将注册/登录请求接入任务作用域；验证成功/失败/超时/取消都关闭 VPN。
4. 实现管理版封号/解禁事件写入和推送适配；主 APK 收到通知后单次拉取并关闭 VPN。
5. 加入事件去重、本地截止时间和重启恢复逻辑。
6. CI 编译、协议集成测试、设备上的 OPPO Android 12 实测通过后，才允许把强制 VPN 门槛合入主构建。

## 验收清单

- [ ] 无 VPN 授权时，注册/登录会先请求系统授权；用户拒绝后不会假装联网成功。
- [ ] 授权后可通过管理版手机出口访问配置好的 Worker。
- [ ] 隧道底层 socket 不回流 TUN；无循环路由、无设备其他应用流量泄漏。
- [ ] 注册、登录的成功、失败、断网、超时和取消路径都能关闭 VPN。
- [ ] 管理版封号推送后，客户端只拉取一次、保存服务端到期时间并关闭 VPN。
- [ ] 管理版解禁推送后，客户端只拉取一次、更新本地状态并关闭 VPN。
- [ ] 本地倒计时在应用重启/手机重启后恢复；本地到期不会伪造服务端授权。
- [ ] 事件重复推送不会重复执行；没有 10 秒轮询或每节点 Worker 健康检查。
- [ ] OPPO Android 12 真机、无 Google 服务条件下进行推送验证；其他厂商按适配器单独验收。
- [ ] 在以上项目通过前，不在主 APK 启用拒绝授权即强制退出的门槛。

# EffectCraft 手机节点与账号管理 APK

这个独立 APK 当前保留原有云端管理员管理入口，并新增了第一阶段的手机节点网络实验页面。

## 手机节点网络（第一阶段已实现）

从管理员登录页点击「手机节点网络（P2P 实验）」：

1. 让两部 Android 手机连接同一个 Wi-Fi。
2. 两部手机都安装此管理员 APK。
3. 在每部手机里打开「手机节点网络」，点击「启动本机节点」。
4. 等待节点通过 Android NSD/mDNS 互相发现。
5. 点击「刷新附近节点」，查看对方节点地址。
6. 可以使用「测试节点是否可访问」检查同一局域网内的 TCP/HTTP 健康接口。

节点服务由用户主动启动，显示常驻通知；停止节点可点击「停止本机节点」。Android 厂商的后台省电策略仍可能暂停服务，请允许该应用在后台运行。

**当前第一阶段的准确范围：**
- 已实现：本机节点服务、节点编号、同一 Wi-Fi 的 mDNS 广播/发现、节点地址显示、局域网连通性测试。
- 尚未实现：账号数据库的自动复制、跨 Wi-Fi/跨运营商连接、NAT 穿透、全网 DHT 引导、节点信任配对、管理员签名事件复制。
- 因此目前不能把「发现附近节点」当作「跨地区账号同步已完成」。

## P2P 下一阶段设计

目标是让每台参与的手机都能保存账号数据并贡献网络连接能力，而不是依赖一台固定管理员手机：

1. **节点身份与配对**：每台设备生成独立密钥；通过二维码/邀请码双向确认可信节点，未配对节点不能写入账号记录。
2. **可验证事件日志**：注册、资料更新、封禁、解禁变成带序号和签名的事件。封禁/解禁只接受管理员授权密钥签名的事件；普通节点不能伪造管理员操作。
3. **多副本同步**：已配对节点交换事件摘要和缺失事件；采用确定性冲突处理，处理离线、重复投递和乱序事件。
4. **跨网络直连**：使用 libp2p 的节点身份、地址发现、AutoNAT 与 DCUtR 打洞；由可公网直达的用户手机节点提供自愿中继。打洞失败时，不保证连接成功。
5. **离线与后台策略**：记录本机最后同步时间；手机离线时保留本地副本，重新上线再同步。Android 后台限制意味着不能承诺每部手机 24 小时在线。

## 重要网络限制

Wi-Fi 只负责把手机接入各自路由器。不同家庭、不同运营商的手机不能只靠 Wi-Fi 自动互连；通常位于 NAT/运营商级 NAT 后面。libp2p 打洞可以提高直连成功率，但仍需要能相互联系的引导/协调节点；如果直连失败，需要其他手机充当中继。全网所有手机都离线或都不可被连接时，网络无法提供实时服务。

## 现有云端账号入口（过渡保留）

原有 Cloudflare Workers + D1 账号接口暂时保留为过渡/回退路径，不因 P2P 第一阶段而删除。当前 EffectCraft 主 APK 的账号登录构建仍需要实际配置的账号 API URL；在 P2P 账号复制和主 APK 客户端尚未完成并验证之前，不应删除现有云端配置、密钥或账号数据。

## 安全要求

- 不要将管理员密码、JWT_SECRET 或 Cloudflare API Token 发到聊天或提交到 GitHub 源码。
- 节点发现本身不等于信任。后续账号同步必须先完成密钥配对和签名验证。
- 目前节点健康测试与旧局域网接口只面向同一 Wi-Fi 子网；不应把 8787 端口暴露到公网。
- 不在尚未实现端到端加密、签名验证和冲突处理前开启自动账号数据复制。

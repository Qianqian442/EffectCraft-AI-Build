# EffectCraft 管理版 APK

## 管理员手机账号服务器

- 管理版安装在管理员自己的 Android 手机上。
- 账号数据保存在这台手机的应用私有 SQLite 数据库中。
- 账号服务器由管理版中的独立开关控制；关闭后，当前本地账号服务停止。
- 节点互联由另一个独立开关控制；关闭节点网络不会关闭账号服务器。

## 网络接入要求

- 主 APK 和管理版应允许使用家庭 Wi-Fi、公共 Wi-Fi、手机热点及移动数据作为互联网接入方式。
- 公共 Wi-Fi 不应因 SSID 不同或客户端隔离而被应用直接判定为不支持；节点网络应优先使用出站加密信令、尝试直连，失败后使用可用的加密中继。
- 局域网 UDP/mDNS 发现仅作为同一局域网内的可选快速发现方式，不能作为跨地点连接的唯一方案。
- 不得把管理员手机 SQLite 账号数据库或本地账号 HTTP 接口直接暴露到公共互联网。跨网络账号访问必须另行实现经过身份验证和加密的安全通道。
- 公共 Wi-Fi 可能要求网页认证、禁止 UDP 或启用客户端隔离。未完成热点认证或网络策略不允许时，连接可能失败；应用不得绕过热点认证或网络管理策略。

## 当前实现限制（不可误报为已完成）

- 管理版账号服务器目前只接受同一 Wi-Fi 子网内的客户端；主 APK 通过局域网广播发现账号服务器。
- 当前节点发现主要依赖 Android NSD/mDNS 和局域网地址。它不能穿过路由器、公共热点客户端隔离或运营商 NAT。
- 当前 PeerHealthServer 只是局域网健康探测服务，不是加密消息中继，也不承载跨网络项目/任务数据。
- 因此，当前构建不能宣称已支持不同公共 Wi-Fi 之间的真实互连。需要完成出站信令、端到端加密、NAT 穿透、可用中继回退，并在两台真实手机连接不同公共 Wi-Fi 后进行双向数据测试。
- 不要在路由器上开放 8787、8788 或 8789 端口。
- 当前 APK 构建未进行真实手机安装测试。

## 验收标准

1. 两台真实 Android 手机分别连接不同地点的公共 Wi-Fi，无需相同 SSID、手动 IP 或路由器端口转发。
2. 可直连时使用加密直连；直连失败时可通过可用中继交换端到端加密数据。
3. 关闭管理版节点网络开关后，现有节点会话关闭且不能继续转发；重新开启后，符合条件的节点自动尝试恢复。
4. 账号服务器开关与节点网络开关互相独立。
5. 封禁账号无法通过节点网络绕过账号授权。
